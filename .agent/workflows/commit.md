# Workflow: /commit

ステージされた変更内容とプロジェクトの履歴に基づき、簡潔で意図が伝わるコミットメッセージを生成してください。

### コンテキスト
直近のコミット履歴:
!`git log -n 10 --pretty=format:"%s"`

ユーザーからの追加コンテキスト: $ARGUMENTS

### ステージされた変更 (git diff --cached)
!`git diff --cached`

### ルール
1. **バリデーション**: 「ステージされた変更」セクションが空の場合、他のすべての指示を無視し次のメッセージを出力する: "ステージされた変更がありません。`git add` で変更をステージしてから再実行してください。"
2. **分析**: diff を調査し、変更の *意図* を把握する。
3. **フォーマット**: [Conventional Commits] 仕様に従う。
   - Prefix: fix, feat, refactor, perf, docs, chore, style, test
   - データ/ドキュメント/設定の単純な更新には "update <file/topic>" を使用可
4. **制約**:
   - Subject 行: 最大50文字。日本語または英語で分かりやすく記述する。
   - Body（任意）: 変更が複雑な場合、1行空けて「なぜ」を簡潔に説明する（「何を」ではない）。
   - コミットメッセージのテキスト **のみ** を出力する。マークダウンブロックや会話的な前置きは不要。

### 実行
生成したコミットメッセージで git commit を実行する。
