# Git ワークフロー & コマンド実行ガイドライン

## 1. GitHub CLI (`gh`) 実行ルール
- **重要**: GitHub CLI ツールを実行する際は、素の `gh ...` ではなく必ず `env gh ...` の形式で呼び出すこと。
  - 例: `env gh pr list`, `env gh pr create`, `env gh issue list`
  - 理由: 権限制御された環境における trusted-CLI シムによるパーミッションエラーを回避するため。

## 2. ブランチ運用 & マージ方針
- ユーザーからの明確な確認がない限り、`master` ブランチに直接コミット・Push を行わないこと。
- 新機能開発や修正の際は、トピックブランチ（例: `feature/...`, `fix/...`）を作成して作業すること。
- CI のテストが成功した場合であっても、ユーザーの明示的かつ曖昧さのない承認なしに PR を自動マージしないこと。
- **PRのマージ方式**: PRをマージする際は、SquashやRebaseではなく**必ず標準のマージコミットを作成する方式 (`env gh pr merge <番号> --merge`)** を使用すること。

## 3. コミット規約
- コミットメッセージは分かりやすく簡潔にし、内容を表す標準的なプレフィックスを使用すること（例: `feat: ...`, `fix: ...`, `docs: ...`）。

## 4. CI ステータスの確認ルール
- PR 作成後やセルフレビュー時など、CI ステータスを確認する際は `env gh pr checks --watch` を使用し、全チェックが完了するまで必ず待機すること。
- CI が Pending の状態で「Pending」としてセルフレビューや完了報告を確定・終了してはならない。
