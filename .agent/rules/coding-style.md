# コーディングスタイル & アーキテクチャガイドライン

## 1. ディレクトリ & コンポーネント構造
- `pages/`: Nuxt のページコンポーネント（ルーティング）。ページコンポーネントは簡潔に保ち、表示や詳細ロジックは `components/` 配下のコンポーネントに委任すること。
- `components/`: 再利用可能な Vue コンポーネント。
- `layouts/`: ページのレイアウト用ラッパーコンポーネント。
- `assets/` & `static/`: CSS、フォント、静的ファイル、画像等。

## 2. Vue / コンポーネント設計ルール
- 単一ファイルコンポーネント (`.vue`) を使用すること。
- Vue コンポーネントの標準的なオプション順序に従うこと：
  `name`, `components`, `props`, `data`, `computed`, `watch`, ライフサイクルフック (`created`, `mounted` 等), `methods`
- クリーンでセマンティックな HTML テンプレートを維持すること。

## 3. リント & フォーマット
- プロジェクトの ESLint (`.eslintrc.js`) および Prettier (`.prettierrc`) の設定に厳格に従うこと。
- 新たなリントエラーを発生させないよう、作業完了前には `pnpm lint` を実行すること。
- TypeScript を使用する箇所では、明示的な型定義・型アノテーションを記述すること。

## 4. パッケージマネージャー & 環境
- パッケージマネージャーには **`pnpm` を絶対に使用** すること (`npm` や `yarn` のコマンド実行・ワークフロー記述は禁止)。
- シェルでコマンドを実行する場合は、`export PATH="$HOME/.local/share/mise/shims:$PATH"` を適用して `pnpm` が参照できるようにすること。
